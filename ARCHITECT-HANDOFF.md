## 2. Standing rules — these were decided, not guessed

**Layout**
- **Header = identity + window chrome only.** Portrait, name, seal, ⋯, window
  modes. No content navigation, ever.
- **Belt = everything inside the character.** Skills · Traits · Actions · Spells ·
  Gear · Craft · Notes.
- **⋯ menu = things that leave the dock or restructure it.** Sync DDB, Edit sheet,
  Level Up, Change character, the ↗ standalone tools.
- **Sizing follows the text, never the viewport.** `max(360px, min(400px × scale,
  100vw))`, scale 1.15/1.3/1.45 → 460/520/580px. Floors: 360 wide, 620 tall; past
  either the shell scrolls rather than the layout folding.

**Rules content**
- **Game rules are written in the VAULT, never in `docs/chapters/`.** Those files
  are generated by `sync_from_vault.py` and anything typed there is erased at the
  next sync. Vault path: `~/obsidian-vault/5.RPG/Fate's Hand/0. D&D 5+ Rules/`.
- Do **not** `git commit` the vault by hand — the Obsidian Git plugin auto-commits
  within seconds and a manual commit sweeps up whatever it was mid-staging.

**Behaviour**
- **Never fall back silently.** If AboveVTT is unreachable, say so and refuse —
  never quietly roll locally while players believe the table saw it.
- **Graceful degradation is the bridge's contract.** Translate what you can, print
  what you cannot.
- **The Brick has no mechanics.** Track that one was granted, which Arcana themed
  it, hold the story, get out of the way. Inventing a spend action contradicts the
  rule (plan §6, vault §5.1).

## 3. Traps already paid for — do not rediscover these

| Trap | What happens | The rule |
|---|---|---|
| `sync_from_vault.py` clobbers the hand-added toolbar in `docs/skill-builder.html` and `docs/stat-roller.html` | two tools ship with no navigation | `git checkout` those two files after every sync, before committing |
| A flex item whose `overflow` is not `visible` gets an automatic minimum size of **0**, not `min-content` | the belt measured **1px** tall in a short window and vanished | `flex:none` on dock chrome; floor the **zone**, never the scroller inside it (a scroller taller than its box overflows the row below) |
| A custom property cannot be defined in terms of itself | `--cd-fs:min(var(--cd-fs),N)` is a cycle and is silently discarded | derive: JS writes `--cd-fs-pref`, CSS computes `--cd-fs` from it, media queries clamp |
| `--cd-width` resolves at `:root` | writing `--cd-fs` on the dock node moved the fonts but left the width pinned | write to `root.ownerDocument.documentElement` — `ownerDocument` keeps Table mode (PiP) correct |
| Cloudflare KV allows ~1 write/sec **per key** | five players rolling at once lose feed events | one key per event + a cursor, never one key for the whole feed |
| `fh-roll/1` is a **view** model | `parts` are display strings like `"d20 (adv)"`; unparseable | machines read the separate `intent` layer (plan §11.2) |
| Codex sometimes pushes straight to `origin/main` | your local `main` is silently behind | `git fetch` and check `origin/main` before assuming you are current |
| `linkedom` lives in `/tmp/fh-player-test` | macOS clears `/tmp`; three integration suites fail for no reason | reinstall: `npm install --prefix /tmp/fh-player-test linkedom@0.18.12`. **Worth moving into the repo as a devDependency** — still outstanding |
| A seq **counter** key re-creates the 1-write/sec limit it was meant to dodge | five players rolling at once race on `feed:{CODE}:cursor` | the sequence IS the timestamp — 13-digit padded epoch ms + random tiebreaker, no shared key (plan §11.4) |
| `addHistory` is **not** where a roll settles | a natural 1 is in history *before* the player chooses, and defying turns it into a 20; an adjusted roll never passes through it at all | broadcast at `openRollState` + the `finish-sequence` branch, gated on `rollTransactionActive()` (plan §11.4b) |
| `document.hidden` is true for the **main** document while Table mode runs in PiP | gating polling on it kills the feed exactly when it is being used at the table | hidden **slows** the poll to 12s, never stops it |
| `~/tools/fh-worker` **has no git** — only timestamped `.bak` files | a bad edit to a live 1500-line Worker is unrecoverable | `cp src/worker.js src/worker.js.bak-$(date +%Y%m%d-%H%M%S)` before editing. **It should be a repo; still outstanding** |
| `WORKER-ADMIN-API.md` in this repo is a **spec**, not the code | you will "fix" a document and deploy nothing | the deployed source is `~/tools/fh-worker/src/worker.js`, `wrangler deploy` from that directory |

## 4. Running the package chats

**Worktrees**, one per package, each with its own port and a pre-built harness so
no chat spends time on setup:

| Worktree | Branch | Port |
|---|---|---|
| `~/tools/fh-worktrees/tarot` | `pkg2-tarot` | 8131 |
| `~/tools/fh-worktrees/abovevtt` | `pkg4-abovevtt` | 8135 |
| `~/tools/fh-worktrees/features` | `pkg5-features` | 8132 |
| `~/tools/fh-worktrees/actions` | `pkg6-actions` | 8133 |
| `~/tools/fh-worktrees/spells` | `pkg7-spells` | 8134 |
| `~/tools/fh-worktrees/notes` | `pkg8-notes` | 8130 |
| `~/tools/fh-worktrees/dice` | `pkg10-dice` | 8136 |

`.claude/launch.json` is tracked but `--skip-worktree`'d in each, so the per-worktree
port never gets committed. Ignore `.claude/worktrees/relaxed-lumiere-*` and
`youthful-taussig-*` — stale, from before this system, not part of it.

**After every push to `main`**, rebase all of them:
```bash
for w in tarot features actions spells abovevtt notes dice; do
  git -C ~/tools/fh-worktrees/$w rebase main -q; done
```

**Refresh a worktree's harness** when core or CSS moves (`site/` is gitignored, so
rebase does not update it): copy `docs/stylesheets/*.css`, `docs/javascripts/*.js`,
`docs/assets/img/tarot/major/*` and `tools/dock-harness.html` into its `site/`.

### Verify, do not trust

Both of the first two packages reported **"terminé / ready to merge"** with
everything **uncommitted** in the working tree — one stray `git checkout` from
gone. Every prompt now says *"reporting is not delivering"*; check anyway:

```bash
git -C <worktree> log --oneline -1        # is there a commit?
git -C <worktree> rev-list --count main..HEAD
git -C <worktree> status --short          # is it clean?
```

Then read the diff before merging. The tarot chat's work was genuinely good and
its report accurate — but reviewing it still found a missing 404 fallback, and
reviewing the Notes merge found a third contract gap nobody had reported (panel
clicks were delegated inside `handleClick`, which bails on non-`<button>` targets).
**The review is where the architect earns the seat.**

### Tests

Six suites, all must stay green:
```bash
for t in tests/*.test.js; do node "$t"; done
```
When a change makes an assertion false, **rewrite it to the new truth and mark it
`REWRITTEN` with the reason** — never loosen it, never delete it. The integration
suite loads the `fh-panel-*.js` files the way the page does; keep that working or
the belt goes untested.

### Deploy
```bash
./.venv/bin/mkdocs gh-deploy --force
```
Docs-only changes (plan, this file) need no deploy — they are not in the built site.
